# Обсуждения и операции D2D 0.5

## Обсуждения

Участник с правом разработки может комментировать задачи и запросы изменений, отвечать, упоминать `@login`, редактировать свои сообщения и отмечать обсуждение решённым. Читатель просматривает сообщения. Правки сохраняют предыдущий текст. Вложения PNG/JPEG/PDF и текстовые файлы — до 4 МиБ, выдаются только действующим участникам проекта.

Комментарий к строке привязан к SHA головы запроса проверки, пути, номеру и стороне diff. Если SHA изменился до отправки, сервер отвечает `409 GIT_CHANGED`. Старые комментарии сохраняются с отметкой предыдущей версии.

- `GET/POST /api/v1/projects/ID/comments`
- `POST /api/v1/projects/ID/comments/update`
- `POST /api/v1/projects/ID/discussion-files`

## Уведомления

Центр в колокольчике показывает ответы, упоминания, события работы, проверки и результаты операций. Можно прочитать отдельное уведомление или все показанные до выбранного времени. После отзыва членства уведомления этого проекта перестают выдаваться. Запросы повторяются каждые 30 секунд; SMTP и push-службы не используются.

## Работа агентов

Токен повторно просматривает только создатель с действующим правом разработки. AES-256-GCM использует локальный ключ `token-vault.key`; хеш токена остаётся источником проверки авторизации. Отозванные и истёкшие токены не раскрываются. Старые токены нельзя восстановить из хеша: сохраните известный токен либо дождитесь API-запроса агента.

Панель получает этапы из `POST /projects/ID/agent-steps`: `generation`, `state`, `stage`, `message`, необязательные `progress` и `commit_sha`. Это отчёт клиента, а не журнал скрытых рассуждений. Ответ содержит `stop_requested`. Агент проверяет его между действиями и подтверждает остановку этапом `state=stopped`. Для немедленного запрета новых действий отзовите токен.

## Управляемые серверы

Администратор на вкладке установки выдаёт команду подключения. Она действует час, содержит отдельный токен и закрепляется за первым `machine_id`. На целевом сервере работает root-служба Python 3 с исходящим HTTPS, Docker Compose и локальными блокировками. SSH-пароль в D2D не передаётся.

Доступны строго выбранные операции: обновить конкретный архив проекта, проверить/перезапустить контейнеры и вернуть сохранённый образ предыдущей версии. Произвольной командной строки API нет. Перед доставкой команды проверяются актуальные права инициатора, токен и поколение агента. При отзыве подключения новые команды запрещены; локальная операция, уже начавшая выполнение, может завершиться.

Результат операции сохраняется на целевом сервере до отправки подтверждения. Потеря HTTP-ответа приводит к повтору подтверждения с тем же ID, а не повторной сборке. Для повторной доставки незавершённой операции выдаётся новая lease. Выполнение сериализовано на сервере и проекте. Проверка контейнеров использует Docker healthcheck, если он объявлен. В интерфейс автоматически передаётся ограниченная сводка статусов, а не полный журнал приложения с возможными секретами.

Откат использует ранее сохранённые локальные ID Docker-образов. Volumes не удаляются, миграции базы автоматически не откатываются. Очистка сохранённых образов Docker делает соответствующий откат невозможным.

## Git и личный откат

Файлы показывают дату первой доступной записи и последнего изменения в выбранной Git-истории. Переименования отслеживаются через `git log --follow`. Существующие файлы и коммиты не получают вымышленную дату импорта.

«Откатить свои» создаёт новый commit revert в ветке действующей сессии. Проверяются принадлежность коммита, поколение, ожидаемая голова и отсутствие конфликта. История не переписывается, force-push не используется. Отменяется **весь коммит**, включая его другие файлы. При неизвестном авторстве старого push кнопка не показывается; авторство новых push и импортов фиксируется D2D.
