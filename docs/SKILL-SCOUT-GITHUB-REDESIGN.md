Источники проверки: package.json, структура web/src, App.tsx, ProjectGit.tsx, styles.css, локальные SKILL.md и инвентаризация установленного. Веб доступен, но внешние кандидаты не потребовались; Directory не использован, достаточно установленного набора. Изображения пользователя — источник визуальных требований.

## 4. Рекомендуемый минимальный набор

1. **design-system** — привести тёмную/светлую палитры, плотность, кнопки, поля, таблицы и вкладки к единому оформлению.
2. **frontend-ui-engineering** — перестроить оболочку и страницы на существующем React/CSS, проверить узкие экраны и клавиатуру.
3. **code-review-and-quality** — проверить изменения и действующие сценарии Git, рабочих сессий, загрузки исходников и установки.

Конкретный объём реализации после согласования:

- Общая оболочка: компактная верхняя панель, поиск, меню пространства, профиль и горизонтальная навигация с подчёркиванием активной вкладки.
- Проекты: плотный список с поиском, описанием, статусом и метаданными; доступная кнопка создания.
- Репозиторий: заголовок и вкладки, панель ветки и действий, таблица файлов, просмотр кода, README при наличии, правая колонка с описанием и версиями.
- Релизы: список версий и отдельные карточки с описанием, датой, тегом и доступными действиями с архивом/установкой.
- Проверка изменений: дерево файлов и читаемый diff с номерами строк и выделением добавлений/удалений на основе реально доступных данных API.
- Задачи, команда, агенты, история, настройки и формы входа: те же общие токены и компоненты.
- Проверка: production-сборка, текущие API-тесты, основные пользовательские действия и визуальная проверка широкого/узкого экрана и обеих тем.

## 6. Конфликты, риски, ограничения

- Указание frontend-ui-engineering не копировать точную компоновку уступает явному запросу пользователя сделать максимально похожий интерфейс. Используем предоставленные визуальные референсы, оставляя название, тексты и данные D2D.
- GitHub содержит функции, которых в D2D пока нет. Не добавлять фиктивные звёзды, форки, Actions, Wiki или счётчики; навигация и действия отражают действительные возможности.
- Политика прав, членство и защита рабочих сессий остаются серверными. Изменение внешнего вида не предоставляет дополнительные права.
- Русские подписи длиннее английских: нужны проверки переполнения, адаптивная навигация и читаемые длинные имена файлов/веток.
- README и diff — недоверенные данные. При форматировании нельзя исполнять HTML/скрипты из проекта; отдельная новая зависимость требует обоснования.
- Используем текстовые инструкции навыков; их вспомогательные скрипты, автоматические установки и внешние сервисы не требуются.
- Переработка UI затрагивает App.tsx и общие стили; нужно проверить все существующие экраны, а не только страницу репозитория.
