# Файлы, папки, ветки и обновления

Доступно с D2D 0.6.0. Git-функции требуют настроенного Forgejo. Наблюдатель читает код и сравнивает версии; запись выполняет текущий исполнитель проекта с правом разработки.

## Загрузка без ZIP

Для нового проекта кнопка **Загрузить проект** в списке проектов также поддерживает ZIP, отдельные файлы и целую папку. Можно задать начальную ветку (например, `develop`) и описание первого коммита. D2D создаст проект, рабочую сессию и снимок для установки. Для файлов и папок нужен настроенный Git.

1. Возьмите проект в разработку и откройте вкладку **Код**.
2. Выберите ветку и перейдите в нужную папку.
3. Нажмите **Загрузить сюда** или **Добавить → Загрузить файлы, папку или ZIP**.
4. Выберите отдельные файлы, целую папку или ZIP. Проверьте папку назначения и список путей.
5. При необходимости включите **Создать отдельную ветку** и задайте имя. Ветка создаётся от выбранной версии; это работает и для ZIP. Первый коммит в пустом репозитории также можно записать в отдельную ветку.
6. Напишите описание изменений и нажмите **Загрузить и сохранить коммит**.

Одна загрузка — один коммит. Файлы с теми же путями заменяются, остальные остаются. Отсутствие файла в загрузке **не удаляет** его из проекта. Для удаления используйте Git. Папка обычно загружается вместе со своим именем; флажок позволяет загрузить только её содержимое. Для ZIP общая обёртка по умолчанию убирается; флажок можно снять. Пустые папки Git не хранит.

Поддерживается до 10 000 файлов за загрузку. Искусственного ограничения размера исходников в МиБ нет: байты передаются потоком на диск. Достаточный свободный диск нужен для загрузки и временного Git-каталога. Удалите `.git`, `node_modules`, `.env` и приватные ключи; `.env.example` разрешён. Символические ссылки и опасные пути не принимаются.

Смена исполнителя, истёкшая сессия и изменение ветки после открытия формы останавливают запись. Силового перезаписывания чужих коммитов нет. Если пропала связь, откройте историю ветки перед повтором: сервер мог успеть сохранить коммит.

## Релизы и красно-зелёные изменения

Релиз закрепляется за конкретным Git-коммитом. В его описание автоматически добавляются изменения относительно предыдущего опубликованного стабильного релиза: добавленные, изменённые и удалённые файлы. Собственное описание релиза сохраняется.

В карточке релиза находятся сравнение с предыдущим релизом, список файлов, кнопка **Красно-зелёный diff** и **Скачать изменённые файлы**. Например, для третьего релиза показывается разница между вторым и третьим. У первого релиза предыдущей версии нет. Переименование в пакете представлено удалением старого пути и добавлением нового; двоичные файлы передаются целиком, а не текстовым патчем. Пакет для выбранного сравнения закреплён за двумя SHA.

## Обновить уже установленное приложение

Вкладка **Установка** и ссылка на неё доступны постоянно, независимо от публикации релиза. Выберите нужную версию; для Git-версии сначала нажмите **Подготовить архив для установки** в карточке релиза. Получите команду установки и выполните на сервере, где уже установлен проект через D2D.

Если исходный архив предыдущей установки сохранён в D2D, установщик скачивает пакет **только изменённых файлов**. Сравниваются точные байты неизменяемых архивов, включая переводы строк CRLF/LF; Git SHA для этого режима не обязателен. Неизменённые исходники копируются из предыдущего каталога установки. Все исходные отслеживаемые файлы проверяются по SHA-256; локальные изменения приводят к остановке, а не перезаписываются. Удаления применяются только к отслеживаемым путям. Код новой версии готовится в отдельном каталоге, затем приложение собирается и запускается обычным способом. Docker может скачивать зависимости и образы заново; экономия касается передачи исходников.

Для первой установки или недоступного исходного архива скачивается полный архив. Старые команды установки D2D также поддерживаются, если сохранились их manifest и исходный архив. Для явного полного скачивания перед выполнением команды можно задать `export D2D_FULL_DOWNLOAD=1`; прежний каталог установки сохранится, но его локальные правки не будут включены в новую копию. Данные приложений и Docker volumes обновлением кода не откатываются. Установочный токен действует один час и закрепляется за сервером; постоянная ссылка на страницу не содержит токена.

Управляемые серверы из панели **Установленные проекты** продолжают выполнять закреплённые команды обновления/отката с полными архивами. Этот режим пока не использует пакеты изменённых файлов; экономное скачивание реализовано для команды установки и ручного пакета.

## Применить скачанный пакет вручную

Пакет содержит `d2d-update.json` с исходной и новой версиями, контрольными суммами и удалениями, а также `files/` с изменёнными файлами. Это **не полный дистрибутив** и не архив для простого распаковывания поверх проекта.

Сохраните резервную копию каталога и скачайте `apply-project-update.py` из того же релиза D2D, что подготовил пакет. Запускайте с правами владельца проекта:

```bash
python3 apply-project-update.py update.zip /srv/my-project --check
python3 apply-project-update.py update.zip /srv/my-project
```

Нужен Python 3.10+. Исходная версия должна точно совпадать с основанием пакета. Скрипт проверяет все исходные отслеживаемые файлы и содержимое ZIP до изменений. Он не заменяет локальные файлы на месте новых путей и не переходит по символическим ссылкам. При обычной ошибке записи возвращает сохранённые файлы. Для гарантии при отключении питания применяйте пакет к отдельной копии исходников и переключайте версию после проверки; установщик D2D делает именно так. После ручного обновления сборку и перезапуск приложения выполняйте по его инструкции.

## API

Все адреса начинаются с `/api/v1`. Чтение требует членства; запись — текущей рабочей сессии и `X-Work-Generation`. Cookie-запросы требуют `X-CSRF-Token`. Токен агента должен иметь `read` и `write` для загрузки.

| Метод и адрес | Назначение |
|---|---|
| `POST /projects/{id}/git/upload` | Одним коммитом добавить файлы, папку или ZIP в выбранную ветку/папку |
| `GET /projects/{id}/git/compare?from=v1&to=v2` | JSON: точные `base_sha`, `head_sha`, файлы со статусами A/M/D/T и текст diff; `format=summary` возвращает список без загрузки diff |
| `GET /projects/{id}/git/compare?from=SHA1&to=SHA2&format=diff` | Полный текст diff для выбранных версий |
| `GET /projects/{id}/git/delta?from=SHA1&to=SHA2` | ZIP только изменённых файлов; SHA-256 ZIP в `X-Checksum-Sha256` |

Параметры загрузки в строке запроса: `branch`, `from` (SHA основания новой ветки), `expected_head` (SHA ветки перед загрузкой), `new_branch=true/false`, `path` (относительный каталог), `message`, `strip_root=true/false` для ZIP. В пустом репозитории `expected_head` и `from` пустые. В непустом точный SHA обязателен. HTTP 409 означает конфликт ветки или рабочей сессии. Загрузка не использует `Idempotency-Key`: защитой повтора служит точный SHA; после потери ответа проверяйте историю.

ZIP отправляется с `Content-Type: application/zip`. Отдельные файлы используют `application/vnd.d2d.files-v1`: 4 байта длины заголовка в big-endian, затем JSON UTF-8 вида `{"files":[{"path":"src/app.ts","size":123}]}`, затем ровно указанное число байтов каждого файла в том же порядке. Заголовок ограничен 4 МиБ; сами файлы передаются без base64. Пример клиента — `web/src/api.ts`, функция `uploadGitFiles`.

## Обновить саму платформу D2D

Команда постоянно отображается внизу интерфейса:

```bash
curl -fsSL https://raw.githubusercontent.com/G0d0v/d2d-platform/main/update.sh | sudo bash
```

`update.sh` поддерживает стандартную Docker-установку `/opt/d2d-community` и существующую системную установку `/opt/d2d` с `/etc/d2d.env`. Он проверяет SHA-256 релиза, готовит новый каталог, создаёт резервную копию и переключает версию. Настройки и секреты не заменяются. Для нестандартного размещения используйте [SELF-HOSTING.md](SELF-HOSTING.md). Код обновляется отдельно от данных: миграции и восстановление БД проверяйте по описанию релиза.

## Быстрая загрузка в 0.6.1

Откройте нужную папку в «Коде» и нажмите «Добавить в эту папку». Выберите или перетащите файлы и папки. Список можно дополнять и убирать отдельные файлы. Перед сохранением проверьте папку, ветку и количество замен; подтвердите замену, если она есть. Заметку можно оставить пустой. Нажмите «Сохранить файлы».

Для обновления одного файла откройте его и нажмите «Заменить файл». Выберите новую версию на компьютере: D2D сохранит прежнее имя и путь. Все изменения попадут в один новый коммит; остальные файлы сохранятся.

Новая папка создаётся вместе с файлами: укажите её путь в блоке «Папка и ветка». Там же можно создать отдельную ветку. ZIP выбирается кнопкой «Загрузить ZIP» и распаковывается в папку назначения. Обычные файлы, включая архивы, выбранные через «Выбрать файлы», сохраняются как файлы.
