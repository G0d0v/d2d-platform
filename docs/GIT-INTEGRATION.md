# Git через Forgejo

D2D остаётся источником членства, ролей, токенов и рабочих сессий. Forgejo слушает только loopback и хранит приватные репозитории; прямой публичный доступ и SSH выключены. Никакие общие учётные данные Forgejo не выдаются клиентам.

Публичный Git HTTP gateway `/git/PROJECT_ID.git` принимает токен D2D через Basic (логин `d2d`, пароль — токен) или Bearer. Чтение требует членства и правильного проекта. Запись требует `write`, свою рабочую сессию и `X-Work-Generation`. Применение push удерживает блокировку `control` до окончания обмена с Forgejo: передача и отзыв либо предшествуют push и запрещают его, либо ждут завершения уже допущенного push.

Ветки, история, файлы, запросы изменений, проверки и версии публикуются через D2D API и русскую оболочку. Код из Git не исполняется внутри D2D. Установщик получает ZIP закреплённого коммита и собирает его на целевом сервере.

Окружение: `FORGEJO_URL` (loopback), `FORGEJO_TOKEN` (секрет служебного аккаунта), `FORGEJO_OWNER` (имя владельца репозиториев). Не включать capabilities, пока адаптер не настроен. Репозиторий получает стабильное имя `project-UUID`.

Для небольшой команды на сервере 1 ГБ сохраняется один процесс API, PostgreSQL и отдельный Forgejo. Нет распределённых очередей и реплик. Масштабирование — сначала память/диск, затем выделенный Git/сборочный сервер. Отказ Forgejo должен возвращать 503 и не влиять на задачи и архивы. Резервные копии Forgejo включаются в ежедневное резервирование.

Оценка архитектуры по system-design: 6/10. Нет отказоустойчивой реплики, внешних резервных копий и распределённого сборщика; для одного предоставленного сервера это явные эксплуатационные ограничения, а не скрытые гарантии.
