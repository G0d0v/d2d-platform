# Серверная установка D2D

Адрес: `https://d2d.darkgpt.cfd`, сервер `168.222.254.212`. Секреты и root-пароль в репозиторий не входят.

nginx TLS → Node.js/Fastify на `127.0.0.1:19090` → PostgreSQL. Приложение работает от `d2d` через systemd. Пользователь приложения не имеет доступа к Docker socket и root.

| Путь | Назначение |
|---|---|
| `/opt/d2d/releases/…` | Проверенные поставки |
| `/opt/d2d/current` | Ссылка на текущую поставку |
| `/etc/d2d.env` | Окружение и секреты, только root |
| `/var/lib/d2d` | Архивы исходников, владелец d2d |
| PostgreSQL `d2d` | Рабочая БД |
| PostgreSQL `d2d_test` | Выделенная тестовая БД |
| `/etc/nginx/sites-available/d2d` | Reverse proxy/TLS |
| `/var/backups/d2d` | Закрытые резервные копии |

Регистрация закрыта приглашениями. Первый аккаунт защищён `SETUP_TOKEN`. Доступ владельца при первой поставке сохраняется отдельным локальным файлом, не входящим в Git или архив приложения.

```bash
systemctl status d2d nginx postgresql
journalctl -u d2d -n 100 --no-pager
curl -fsS http://127.0.0.1:19090/health
curl -fsS https://d2d.darkgpt.cfd/health
systemctl list-timers d2d-backup.timer certbot.timer
```

Сертификат продлевает certbot, nginx перечитывает его через deploy hook. На сервере 1 ГБ swap, процесс приложения ограничен `MemoryMax=512M`.

Ежедневный `d2d-backup.timer` сохраняет дамп PostgreSQL, архивы и конфигурацию. Копии старше трёх суток удаляются. Это копии на том же сервере; для защиты от потери сервера нужно внешнее хранилище.

```bash
systemctl start d2d-backup.service
ls -lh /var/backups/d2d
```

Перед обновлением выполнить резервирование. Новую поставку распаковать в новый `releases`, выполнить `npm ci`, проверки и сборку. После успеха переключить `current`, перезапустить службу и проверить `/health`. Секреты, БД и архивы находятся вне поставки.

При сбое кода вернуть `current` на предыдущую поставку. Миграции этой версии аддитивные; совместимость будущих схем следует проверять перед откатом.

Дамп сначала восстановить в отдельную пустую БД через `pg_restore`, сопоставить с архивами из той же копии. Переключать рабочую БД только после проверки и остановки приложения. Docker volumes устанавливаемых проектов сохраняются отдельно средствами самих проектов; копия платформы их не содержит.
