# Проверка D2D 0.6.0

Дата: 15 ноября 2026. Проверялся код выпуска и изолированный экземпляр с настоящим Forgejo на Linux. Рабочие проекты для тестов не использовались.

## Автоматические проверки

- `npm test`: 35 успешных проверок, один интеграционный сценарий Forgejo пропускается без его параметров. Всего 36 тестов.
- `npm run build`: TypeScript и production-сборка Vite проходят.
- `npm audit --omit=dev --audit-level=high`: уязвимости производственных зависимостей не найдены.
- Отдельный запуск `server/git.test.ts` с настоящим Forgejo: 3/3 успешных сценария, без пропусков.
- Синтаксис Bash проверяется для `install.sh`, `update.sh`, установщика проекта и существующих серверных скриптов; Python-скрипты компилируются в CI.

## Браузерная проверка

В изолированном экземпляре через браузер выполнены:

- загрузка обычного файла в `docs` новой ветки с описанием коммита;
- загрузка папки с вложенным файлом; каталог сохранился после коммита;
- создание нового проекта из папки без ZIP с первой веткой `develop`;
- просмотр сравнения двух релизов, красно-зелёного diff и скачивание пакета через ссылку;
- проверка ширины 390 px и светлой темы: горизонтального переполнения страницы не обнаружено; навигационные полосы прокручиваются отдельно;
- проверка постоянной команды обновления внизу страницы.

Скриншоты настоящего тестового интерфейса: [импорт папки](images/file-upload.png), [сравнение релизов](images/release-compare.png). Это временные тестовые проекты, а не рабочий код пользователя.

## Границы проверки

Установщик проекта проверен на Docker-приложении. Скрипт обновления самой платформы поддерживает стандартные Docker- и системную установки; производственный результат фиксируется дополнительно после публикации пакетов GitHub. Произвольные пользовательские Compose-файлы, все комбинации обновлений и отключение питания во время ручного изменения каталога не моделировались. Ручной скрипт возвращает файлы при обычной ошибке, но для устойчивости к потере питания нужна отдельная копия каталога.

По диагностике Release It подтверждены 2/8 пунктов: ограниченные по времени внешние Git-операции и проверки сбоев/конфликтов. Не заявлены: circuit breaker (нужен отдельный автомат отключения Forgejo после ошибок), изоляция очередей по проектам (нужны отдельные очереди вместо общей блокировки записи), обновление без остановки (нужно переключение двух экземпляров), общая readiness-проверка Git и БД (нужны раздельные liveness/readiness), сквозной ID операции в сохранённых событиях (нужно связать его с request ID) и нагрузка выше ожидаемого пика (нужен отдельный нагрузочный стенд). Эти системные улучшения не являются реализованными функциями релиза.
