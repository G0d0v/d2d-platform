# Skill Scout: обсуждения, уведомления, установленные проекты и панель агентов

Дата: 14 ноября 2026. Статус: согласовано пользователем, реализация выполнена.

## 1. Анализ задачи

D2D 0.4.0 — русская платформа совместной разработки. Требуются четыре связанные функции: обсуждения задач/изменений, личные уведомления, управление установленными проектами и панель работы ИИ-агентов.
Проверенный стек: React 19, TypeScript, Vite 7, Fastify 5, PostgreSQL/PGlite, приватный Forgejo. Разработка на Windows; опубликованная платформа работает на Linux.
В коде уже есть задачи, рабочие сессии, история событий, агенты с ограниченными токенами, Git review, установочные архивы и результаты установки. Комментариев, личного inbox, постоянного контроля серверов и отдельных отчётов о выполнении агента пока нет.
Компетенции: модель данных/API, интерфейс и доступность, авторизация/вложения, надёжные команды серверу, диагностика и доставка событий.
Уже доступны и пригодятся: пять установленных навыков ниже, текущие npm-проверки и браузер CUA. Новые SaaS, MCP, Redis, SMTP и провайдеры LLM не требуются.
Источники проверки: package.json, server/db.ts, model.ts, source-routes.ts, mcp.ts, ProjectTasks.tsx, существующие Git/UI-модули и локальные SKILL.md. Веб доступен, внешние кандидаты и Directory не использованы: установленного набора достаточно. Секреты в исследование не передавались.

### Порядок и приёмка

1. Зафиксировать API, модель прав и миграции. Существующие архивы, сессии, агенты и установки должны сохраниться.
2. Реализовать обсуждения и личный inbox на единой модели событий; проверить повторы, параллельные ответы, упоминания, вложения и отзыв членства.
3. Реализовать отчёты ИИ-агента и панель; проверить передачу проекта, устаревшее поколение, пропажу heartbeat и запрос остановки.
4. Реализовать отдельное подключение сервера, очередь ограниченных команд и панель установок. Техническим прототипом проверить потерю ответа, повтор получения команды, одновременные обновления и восстановление после перезапуска.
5. Проверить установку/обновление/откат на тестовом приложении, а не на рабочем PSModule. Существующий факт установки сам по себе не предоставляет постоянного доступа: старые серверы показывать как «не подключён к управлению» до подключения.
6. Пройти `npm test`, `npm run build`, браузерные проверки обеих тем и узких экранов. Обновить OpenAPI, руководство API/MCP и инструкции подключения сервера, затем опубликовать обновление D2D с резервной копией.

## 5. Опционально

- Telegram-уведомления и browser push можно добавить позднее: сейчас центр уведомлений работает внутри D2D, SMTP не добавляется.
- Внешний мониторинг, новые MCP и субагенты для этой реализации не нужны.
- Автоматический запуск платных LLM и управление процессом стороннего агента на компьютере пользователя не входят в запрос. Панель работает с подключёнными агентами через доступный протокол.

## 6. Конфликты, риски, ограничения

- Постоянный доступ к серверу — новая явная возможность. Предлагается отдельное подключение с отзывом токена и ограниченным набором действий, без хранения SSH-паролей в D2D и без произвольной удалённой shell-команды из интерфейса.
- Серверный исполнитель и ИИ-агент — разные сущности с разными токенами. Токен одного не должен подходить к API другого.
- Сохраняется текущая политика: администратор проекта управляет установкой; агент с write может выполнять разрешённые операции только со своей актуальной рабочей сессией. Наблюдатель не получает право записи. Обсуждение человеком не требует захвата проекта.
- Вложения обсуждений — новый обработчик загрузки: отдельное хранилище, проверка имён/содержимого и авторизация скачивания. Ограничения вложений не возвращают снятый лимит размера ZIP-исходников.
- Логи сервера и сообщения агента недоверенные. Нельзя хранить целиком окружение/командные строки с токенами или исполнять их как инструкции.
- «Нет связи» означает отсутствие свежих данных; это не доказательство остановки приложения или завершения агента. Запрос остановки ИИ-агенту не означает, что D2D умеет завершить процесс стороннего клиента.
- Откат приложения возвращает сохранённую версию кода/образа. Откат миграций БД автоматически не обещается; совместимость схемы и резервные копии должны учитываться отдельно.
- Для первых версий достаточно ограниченного по частоте обновления состояния. Не менять стек и не добавлять Redis/WebSocket-инфраструктуру без необходимости.
- Предыдущий Skill Scout покрывал редизайн, а этот отчёт — новый функциональный объём. После согласования повторный Scout для этих четырёх функций не требуется.
