# Загрузка и установка исходного проекта

Администратор загружает ZIP через «Загрузить проект» или вкладку «Исходники и установка». Запись фиксирует SHA-256, список файлов, автора и время. Повтор того же ZIP в тот же проект возвращает существующую версию.

Распознаются корневые `compose.yaml`, `compose.yml`, `docker-compose.yml`, `docker-compose.yaml`, `Dockerfile` и `package.json`. Обёртка одной общей папкой поддерживается. Перед установкой проверьте порты, переменные окружения, пути данных и healthcheck.

Команда действует час, связана с одной установкой и первым hostname сервера. Текущие права выдавшего пользователя, состояние проекта, а для агента также его токен и рабочая сессия проверяются при обращении. В БД хранится только хеш токена. Рецепт фиксируется при выдаче команды.

Нужны root, Docker Engine/Compose v2, Python 3, curl, sha256sum и flock. Если Docker отсутствует, на Debian/Ubuntu он устанавливается пакетами дистрибутива. На других дистрибутивах установите Docker/Compose заранее.

Установщик закрепляет запрос за сервером, блокирует параллельную установку проекта, скачивает архив, проверяет SHA-256/CRC/пути, распаковывает отдельную версию и выполняет `docker compose up --build --wait`. Проверки приложения выполняются, если объявлен healthcheck. Ссылка `current` переключается после успеха. Результат отправляется в D2D.

Сбой связи после локального успеха не откатывает работающую версию. Повтор команды сверяет локальный архив и рецепт, проверяет контейнеры и повторно сообщает результат. При ошибке сборки/запуска установщик пытается поднять предыдущую Compose-конфигурацию. Каталоги версий и volumes не удаляются. Миграции данных должны иметь собственную стратегию обратной совместимости/отката.

Для постоянных данных используйте именованные Docker volumes или стабильные абсолютные bind-пути вне `releases`. Секреты настраивайте на целевом сервере. Для Compose относительные пути разрешаются относительно исходного файла. Для Node.js/Dockerfile порт привязывается к `127.0.0.1:PORT`; внешний домен и TLS требуют nginx/Caddy. Для Compose действуют порты из файла проекта.

Переменные окружения для Node.js/Dockerfile можно заранее сохранить на целевом сервере в `/opt/d2d-projects/PROJECT_ID/data/app.env` (права 600). Для подстановки переменных Compose используется `data/compose.env`. Эти файлы не загружаются в D2D и сохраняются между версиями. Для самой D2D при установке в контейнере нужно задать `PUBLIC_ORIGIN` по реальному адресу экземпляра.

После сборки/получения образов установщик закрепляет их точные локальные ID в конфигурации версии. Откат использует эти ID, а не перезаписанный `latest`.

| Метод и маршрут | Назначение |
|---|---|
| `POST /api/v1/projects/ID/source` | ZIP как `application/zip`; CSRF, `X-Filename` (URL-encoded), `X-Work-Generation` при активной работе |
| `GET /api/v1/projects/ID/source` | Версии и результаты установок |
| `GET /api/v1/artifacts/ID/download` | Скачать ZIP с проверкой членства |
| `GET /api/v1/artifacts/ID/file?path=…` | Предпросмотр до 256 КиБ |
| `PATCH /api/v1/artifacts/ID/recipe` | Тип `compose`/`dockerfile`/`node`/`none`, путь и порт; Idempotency-Key |
| `POST /api/v1/artifacts/ID/installations` | Выдать команду установки; показывается один раз, автоматического повтора нет |

При загрузке в занятый проект проверяются исполнитель и поколение. Токен агента с правом `write` может загрузить исходники, настроить запуск и выдать установочную команду. Для всех трёх операций обязательна собственная действующая рабочая сессия и заголовок `X-Work-Generation`. Отзыв/истечение токена, передача/завершение сессии блокируют выданную им команду. Пароль целевого сервера в D2D не передаётся.

Размер ZIP и отдельных файлов не ограничен платформой; файлы принимаются и отдаются потоком. Практический предел — свободное место на сервере. Проверки путей, CRC, приватных ключей и максимум 10 000 файлов сохранены. nginx должен использовать `client_max_body_size 0` и `proxy_request_buffering off`.
