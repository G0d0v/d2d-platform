# Локальная альфа D2D

Основание: согласованный план LunaForge от 14 ноября 2026 года. В этом репозитории сохраняем название D2D и независимость от PSModule.

## Контракт первого сценария

Вход по логину и паролю → проект → задача → эксклюзивная рабочая сессия → передача с заметкой → завершение. API `/api/v1`, русские сообщения и стабильные коды ошибок. Авторизация едина для сайта и ограниченных токенов агентов. Восстановление по одноразовому резервному коду, без SMTP.

Мутации используют `Idempotency-Key`, ключ связан с исполнителем, методом, маршрутом и каноническим телом. Повтор другого тела возвращает `409`. Ключи не удаляются автоматически в альфе. Версии задач передаются через `If-Match`; поколение рабочей сессии — в теле запроса. Истечение срока блокирует запись; heartbeat не продлевает срок.

## Границы компонентов

Fastify → авторизация → доменные операции → PostgreSQL. Локально используется PGlite с тем же SQL. Проверка и изменение выполняются в одной транзакции; строка `control` сериализует мутации небольшой команды, строка проекта и частичный уникальный индекс дополнительно защищают владение. Это осознанное ограничение пропускной способности альфы. При подключении PostgreSQL тесты должны запускаться с `TEST_DATABASE_URL`, отдельно от рабочих данных.

Плановая нагрузка — 2–10 участников, десятки проектов, до нескольких запросов в секунду. Сначала вертикальное масштабирование PostgreSQL и измерение времени ожидания блокировок. Кэш не требуется: права и владение читаются из БД. Серверные журналы содержат request ID, доменные события — исполнителя и ответственного человека. Высокая доступность и мониторинг производства относятся к этапу серверной установки.

## Git и развёртывание

Forgejo является будущим источником Git/PR; таблицы `project_files`, `changes`, `releases` из исходного каркаса не используются как замена Git. Пока нет проверенного строгого Git-входа, запись кода, слияние, сборки, релизы и деплой выключены. Неизвестный результат внешней операции нельзя считать успехом.

Приёмка интеграции требует настоящего Forgejo и PostgreSQL: HTTP push, отзыв токена, гонка push/передача, остановка процесса во время записи, сверка refs, запрет обхода через API/SSH/редактор. Тест HTTP-адаптера с заглушкой не заменяет эту проверку. PSModule и удалённые серверы не изменяются.

## Поставка

Локальные проверки: `npm run check`, `npm test`, `npm run build`. Рабочие данные — `.d2d`, секреты не входят в Git. После успешных проверок приложение запускается только на loopback. Размещение и production CI включаются после выбора сервера и проверки интеграции; локальный скрипт проверок служит тем же входом для будущего runner.

## Оценка архитектуры

По диагностике навыка system-design: 6/10 для локального контура (5 из 8 пунктов). Определены требования, нагрузка, стратегия БД, журналы и локальная поставка. Не закрыты избыточность компонентов, кэширование нагруженных чтений и очередь фоновых операций. Для локальной альфы они не вводятся: серверный этап должен определить резервирование и алерты, измерить чтения перед добавлением кэша и реализовать PostgreSQL outbox/очередь перед включением сборок и деплоя.
