## Подтверждённые ошибки

### A01 · P1 · Старая форма завершает новую рабочую сессию

**Воспроизведено в браузере и API.**

1. Начать сессию A и открыть «Завершить». Ввести итог A, оставить окно открытым.
2. Из второго клиента того же пользователя завершить A и начать B.
3. Дождаться фонового обновления страницы. Черновик A остаётся в открытом окне.
4. Нажать «Завершить работу». Приложение успешно завершает B с итогом A.

На стенде A имела поколение 1, B — 2. В истории после события начала «НОВАЯ сессия — НЕ завершать старым черновиком» появилась запись завершения с текстом «Итог СТАРОЙ сессии: проверка формы завершена».

Причина: окно хранится как строка `modal`, а `workAction` берёт ID и поколение из текущего `work`, который обновляет polling. Сервер получает уже новое поколение и поэтому законно принимает запрос. Тесты защиты от старого поколения не проверяют эту ошибку клиента.

Исправление: при открытии формы фиксировать `projectId`, `sessionId`, `generation` и тип действия. При смене сессии сохранять черновик, блокировать отправку и объяснять, что работа изменилась. Не подменять поколение автоматически. Проверить таким же способом передачу и запрос передачи.

### A05 · P2 · Истёкший токен агента оставляет проект занятым

**Воспроизведено в изолированной БД с принудительным истечением времени токена.**

Агент начинает сессию; его токен истекает раньше срока сессии. Завершение от агента возвращает 401, а попытка человека начать работу — 409 `PROJECT_BUSY`. В проверке до конца сессии оставалось 120 минут. Администратор может вручную отозвать токен либо передать сессию, но обычный разработчик сам её не освободит.

Причина: доступ агента проверяется по сроку токена, `currentWork` — только по сроку сессии. Явный отзыв закрывает сессию, автоматическое истечение токена — нет.

Исправление: определить явную политику этого состояния. Для текущей альфы ограничить срок сессии/продления сроком токена либо переводить работу в состояние, требующее принятия человеком, с доступным действием и уведомлением. При подключении Git автоматическое освобождение должно согласовываться с гарантией завершения или запрета уже начатых записей.

Код: [авторизация агента](C:/Users/godovqqw/d2d-platform/server/auth.ts:11), [currentWork](C:/Users/godovqqw/d2d-platform/server/model.ts:26), [явный отзыв](C:/Users/godovqqw/d2d-platform/server/app.ts:260).

### A06 · P2 · «Обновить» в ошибке входа отправляет форму

**Воспроизведено в браузере.**

Ввести неверный пароль, получить ошибку, исправить поле пароля и нажать «Обновить». Вместо одного обновления состояния происходит вход в аккаунт.

Причина: кнопка в `ErrorBox` не имеет `type="button"`; внутри формы она является submit. Компонент используется также в формах регистрации и восстановления — там следует отдельно проверить отсутствие непреднамеренной отправки.

Исправление: явный тип кнопки, отдельная команда повторной отправки там, где она действительно нужна; остальные ошибки должны подсказывать исправление конкретного поля.

### A07 · P2 · Сигнал активности зависит от открытого раздела

**Установлено по коду; отдельное трёхминутное воспроизведение не проводилось.**

Heartbeat запускается только для `work` текущего детального проекта. При переходе в документацию, «Мою работу», список или другой проект этот таймер снимается. Пользователь продолжает работать в приложении, но спустя три минуты коллега может увидеть «Связь потеряна». Несколько одновременно занятых человеком проектов обслуживаются только по открытому проекту.

Исправление: отправлять heartbeat для всех принадлежащих этому клиенту активных сессий из отдельного менеджера сессий; различать связь с клиентом и присутствие на конкретном экране. Предупреждать об истечении срока и отдельно объяснять, что heartbeat не продлевает владение.

## Технические ограничения и границы проверки

- Forgejo/Git, PR, сборки, релизы, развёртывание и MCP отсутствуют и честно выключены в capabilities. Это незавершённые части исходного продукта, а не найденная регрессия. Рабочая сессия сейчас защищает координационные операции, но ещё не запись Git.
- Все мутации, включая вход и вычисление пароля, сериализуются через одну строку `control`. Чтение списков сначала получает весь набор данных, затем режет страницу в памяти; список проектов дополнительно запрашивает работу каждого проекта. Это известный предел локальной альфы, не доказанная проблема производительности при текущей малой нагрузке. Перед серверным этапом нужны измерения и SQL-пагинация.
- Реальный PostgreSQL, multi-process нагрузка и гонка push/передача Forgejo в этом аудите не проверялись. Зелёные тесты PGlite не закрывают эти гарантии.
- Автоматические тесты в основном проверяют API. Они не ловят устаревшие открытые формы, неполный личный список и поведение кнопок внутри форм. Нужны браузерные регрессии для A01, A02 и A06.
- Не проведён полный аудит безопасности или сертификация доступности. Подтверждённые проблемы перечислены выше; отсутствие других найденных проблем не означает их отсутствия.

## Порядок исправлений и приёмка

1. **Целостность действий:** привязка формы к ID/поколению; после смены сессии старый черновик не меняет новую работу. Кнопка обновления ошибки не отправляет форму.
2. **Повседневная работа:** редактирование задач, управление членством и ролями; полный поиск/личные сессии независимо от пагинации; доступ к задаче №501.
3. **Непрерывность контекста:** последний итог доступен новому человеку и агенту; запросы передачи имеют решение/отмену; истёкший токен не оставляет необъяснимую занятую работу; heartbeat не зависит от раздела.
4. **Удобство:** карточка задачи, компактная доска/список, мобильный режим, читаемый текст, блок внимания, настройки безопасности.
5. **Полный продукт:** технический прототип реального Forgejo и PostgreSQL с проверкой push/передачи, затем Git/PR и дальнейшие этапы согласованного плана.

После исправлений повторить не только существующие 16 тестов, но и описанные воспроизведения. Отдельно проверить поведение при потере ответа, открытых двух вкладках и изменении прав во время открытой формы.
