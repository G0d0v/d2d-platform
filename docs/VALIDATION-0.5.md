- `npm test`: 32 проверки пройдены, 1 интеграционная проверка Forgejo явно пропущена без локального секрета. Ошибок нет.
- `npm run build`: TypeScript и Vite проходят.
- `npm audit --omit=dev`: уязвимостей не обнаружено.
- GitHub Actions: [проверка исходного релиза](https://github.com/G0d0v/d2d-platform/actions/runs/43629457176) и [проверка исправлений установки](https://github.com/G0d0v/d2d-platform/actions/runs/43629798073) завершились успешно. Node.js 24, тесты, сборка, аудит production-зависимостей, `bash -n` и компиляция Python.
- Новый набор проверяет чужой и отозванный доступ, шифрование и повторное раскрытие токена, обсуждения и правки автора, вложения, уведомления, поколение агента, запрос остановки, привязку сервера и повторное сохранение результата команды.

## Настоящий Git

На сервере с Forgejo 17.0.1 повторно выполнены все три Git-проверки: без пропусков и ошибок. Полный сценарий включает clone/push, передачу во время push, ветки, PR, независимую проверку, merge, релиз, архив установки, даты файлов, историю и красно-зелёный diff, комментарий к строке и откат своего коммита. Тестовые репозитории имеют отдельные UUID и удаляются после проверки; репозитории пользователей не изменялись.

## Серверный исполнитель

На отдельном экземпляре D2D с PostgreSQL и Forgejo установлена настоящая root-служба подключения. Отдельное приложение BusyBox с Docker healthcheck проверено HTTP-запросами после операций:

| Операция | Результат |
|---|---|
| Установка v1 | `succeeded`, HTTP отдаёт v1 |
| Обновление до v2 | `succeeded`, HTTP отдаёт v2 |
| Откат образа до v1 | `succeeded`, HTTP отдаёт v1 |
| Перезапуск | Контейнер проверен, HTTP отдаёт v1 |

После обнаруженной при проверке проблемы служба получила отдельные `HOME` и `DOCKER_CONFIG`; защита домашнего каталога root сохранена. Перезапуск выполняет реальный Docker restart и проверяет готовность контейнеров.

В отдельном сценарии прокси один раз возвращает 503 вместо приёма результата. Исполнитель сохраняет квитанцию, повторно получает ту же команду с новой lease и отправляет результат повторно. Сделаны две попытки подтверждения. Время запуска контейнера изменилось один раз, а между первой и повторной отправкой осталось одинаковым. В БД итог `succeeded`.

## Установка платформы одной командой

Опубликованный установщик скачан с GitHub и выполнен с `D2D_VERSION=v0.5.0-rc.1` и `--local 19102`. Он самостоятельно скачал и проверил релиз, собрал образ и запустил PostgreSQL и D2D с приватным Forgejo. Проверены:

- код первоначальной настройки и создание первого аккаунта;
- импорт ZIP в настоящий Git и чтение README;
- clone через Git gateway;
- даты и история файла;
- повторный просмотр токена;
- перезапуск контейнера с сохранением БД, репозитория и ключа токенов;
- доступ только на loopback, без публикации Forgejo и PostgreSQL.

После проверки тестовые контейнеры, volumes и временный кэш сборок удалены. Основная платформа и её данные сохранены. HTTPS самостоятельного экземпляра проверяется конфигурацией Caddy; получение настоящего сертификата для нового домена требует корректного DNS и свободных 80/443. Полная пробная установка выполнена в локальном HTTP-режиме.

## Публикация основного экземпляра

Обновлён [d2d.darkgpt.cfd](https://d2d.darkgpt.cfd), каталог `/opt/d2d/releases/20261114-07`. До переключения создана согласованная копия PostgreSQL и файлов `d2d-20261114-190127`. Ссылка `current` переключена атомарно, при неуспешной проверке запуска предусмотрен возврат на предыдущий код.

Через опубликованный HTTPS API проверены capabilities 0.5, даты и история реального файла, diff, повторный просмотр токена, обсуждение, этапы агента, запрос остановки и его подтверждение, завершение сессии, отзыв тестового токена, OpenAPI и JS/CSS production-сборки. Запись выполнялась только в ранее выделенном тестовом проекте с одним владельцем. Сервисы d2d, forgejo и nginx активны, `/health` возвращает `{"ok":true}`. Ключ токенов принадлежит d2d с правами 600.

## Границы проверки

Новая визуальная проверка через браузер не выполнена: управление браузером отключено в настройках Work. Сборка, проверки API и реальные Git/Docker-сценарии выполнены. Изображение README — ранее проверенный реальный экран версии оформления 0.4, это явно подписано.

Остановка агента — кооперативный запрос клиенту; отзыв блокирует новые API/Git-действия. Уже начатая операция на подключённом сервере может завершиться после отзыва подключения. Откат возвращает сохранённый образ, но не миграции данных. Автоматически передаваемые диагностические сведения ограничены статусами контейнеров, полный журнал приложения не запрашивается. Старый токен, доступный только как хеш, появляется для повторного просмотра после API-запроса агента либо ручного сохранения известного токена.
